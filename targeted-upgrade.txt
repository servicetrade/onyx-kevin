6. `docker-compose -f docker-compose.prod-no-letsencrypt.yml -p danswer-stack up -d`

### Issue 1: api_server crash loop — set concatenation TypeError
- **Symptom**: api_server container in "Restarting" state, 502 from nginx
- **Error**: `TypeError: unsupported operand type(s) for +: 'set' and 'set'` in llm_provider_options.py:82
- **Cause**: litellm 1.81.3 changed `bedrock_models` and `bedrock_converse_models` from list to set
- **Fix**: `list(litellm.bedrock_models) + list(litellm.bedrock_converse_models)` (commit 233dac29a)
- **Resolution**: Rebuilt Docker image and restarted stack

### SQL Migration Executed
After containers came up:
```bash
# Verified llm_provider_id
docker exec -it danswer-stack-relational_db-1 psql -U postgres -d postgres -c "SELECT id, name FROM llm_provider;"

# Cleared old models
docker exec -it danswer-stack-relational_db-1 psql -U postgres -d postgres -c "DELETE FROM model_configuration;"

# Inserted Claude 4.5 models with 200K context windows
docker exec -it danswer-stack-relational_db-1 psql -U postgres -d postgres -c "INSERT INTO model_configuration (name, is_visible, llm_provider_id, max_input_tokens) VALUES ('us.anthropic.claude-haiku-4-5-20251001-v1:0', true, 3, 200000), ('us.anthropic.claude-sonnet-4-5-20250929-v1:0', true, 3, 200000), ('us.anthropic.claude-opus-4-5-20251101-v1:0', true, 3, 200000);"

# Set Haiku as default
docker exec -it danswer-stack-relational_db-1 psql -U postgres -d postgres -c "UPDATE llm_provider SET default_model_name = 'us.anthropic.claude-haiku-4-5-20251001-v1:0' WHERE name = 'AWS Bedrock';"
```

### Issue 2: Vespa 503 — search unavailable after stack restart
- **Symptom**: Can log in, can select Claude 4.5 models from dropdown (friendly names work!), but chat fails with "Failed to query Vespa" / 503
- **Cause**: NOT related to our changes. Vespa is loading a massive index (~65GB RAM for proton process). This happens after any full stack restart.
- **Vespa loading progress** (from proton logs):
  - Loading attributes one by one from disk
  - `blurb` attribute: 255 seconds (4+ min)
  - `embeddings` attribute: 733 seconds (12+ min)
  - `title_embedding` attribute: started loading, estimated similar duration
  - After all attributes load, transaction log replay may follow
- **Health check**: `docker exec danswer-stack-index-1 curl -s http://localhost:8081/state/v1/health | grep code`
  - Shows `"initializing"` until all data is loaded, then flips to `"up"`
- **Resolution**: Wait. Vespa needs 20-30+ minutes to fully load this index after a restart.

## Key Learnings
1. **litellm 1.81.3 changed bedrock_models/bedrock_converse_models from list to set** — broke concatenation with `+`. Need `list()` wrapper.
2. **Vespa takes 20-30+ minutes to restart** with large indexes. Plan for this during deployments.
3. **SQL migration is essential** — without model_configuration rows with max_input_tokens=200000, context windows fall back to 4096 tokens.
4. **Docker build is required** — staging uses pre-built images, not local code. Must `docker build -t onyxdotapp/onyx-backend:latest` after code changes.
5. **Use `docker-compose` (with hyphen)** on the staging box, not `docker compose`.
