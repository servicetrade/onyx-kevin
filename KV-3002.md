# KV-3002: Fix Pre-existing Bugs on servicetrade Branch

## Summary

Fix bugs and code quality issues found on the `servicetrade` branch during KV-3001 code review. These are pre-existing issues, not regressions from the model upgrade work.

## Bugs

### Bug 1: SlackChannelConfig.from_model passes raw ORM objects

**File:** `backend/onyx/server/manage/models.py:296-298`

`SlackChannelConfig.from_model()` passes raw SQLAlchemy ORM objects for `standard_answer_categories` instead of converting to Pydantic models. FastAPI serialization will fail or produce unexpected output when any Slack bot admin endpoint is called (`GET /admin/slack-bot/config`, `POST /admin/slack-bot/channel`, etc.).

**Fix:** Replace:
```python
standard_answer_categories=list(
    slack_channel_config_model.standard_answer_categories
),
```
With:
```python
standard_answer_categories=[
    StandardAnswerCategory.from_model(m)
    for m in slack_channel_config_model.standard_answer_categories
],
```

Also remove the `ConfigDict(arbitrary_types_allowed=True)` workaround that was added to suppress the validation error.

**Call sites:** `backend/onyx/server/manage/slack_bot.py` lines 153, 216, 239, 355.

### Bug 2: DEFAULT_PERSONA_ID hardcoded to staging-specific ID 11

**File:** `backend/onyx/configs/constants.py:48`

Changed from `0` (built-in "Search" persona that exists in all deployments) to `11` (a custom persona specific to the staging box). Breaks chat, Slack bot, and agent search on any other deployment.

**Fix:** Revert to `DEFAULT_PERSONA_ID = 0` or make configurable via `DEFAULT_PERSONA_ID` environment variable.

## Critical Issues

### Critical 1: SQLAlchemy error details leaked in API response

**File:** `backend/onyx/server/manage/reports.py:62`

The error handler exposes internal DB details (table names, column names, query fragments) in 500 error responses. Admin-only but still a security concern.

**Fix:** Log the actual error server-side, return a generic message:
```python
logger.error(f"Database error in chat-session-groups: {e}")
raise HTTPException(
    status_code=500,
    detail="An internal error occurred while fetching chat session data.",
)
```
