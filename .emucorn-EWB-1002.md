## Story Details
**Jira Key**: EWB-1002
**Title**: Fix Missing Sidebar Assistants After v2.5.9 Upgrade
**Type**: Bug
**Priority**: High
**Status**: In Progress

**Description**:
After upgrading Kevin AI from v0.28.2 to v2.5.9, users see an empty "Agents" section in the sidebar instead of the expected list of assistants.

**Current State**:
- Database has all personas with correct flags: `is_default_persona=true`, `is_visible=true`, `is_public=true`, `deleted=false`
- User has `pinned_assistants=NULL` which should trigger fallback to show default personas
- API endpoint `/api/persona` needs verification - may not be returning built-in personas (negative IDs)
- UI shows empty "Agents" section with only "Explore Agents" link

**Technical Context**:
The sidebar structure changed significantly in v2.5.9:
- Old (v0.28.2): Shows all visible assistants in "Assistants" section
- New (v2.5.9): Shows only "pinned agents" in "Agents" section

Key Code Path:
1. `AgentsContext.tsx` line 56-67 - `getPinnedAgents()` function:
   - If `pinnedAgentIds` is NULL → returns `agents.filter(agent => agent.is_default_persona && agent.id !== 0)`
   - If `pinnedAgentIds` is `[]` → returns empty array

2. `AppSidebar.tsx` line 131, 148-151, 458-459:
   - Gets `pinnedAgents` from context
   - Builds `visibleAgents` from `pinnedAgents` + `currentAgent`
   - Renders only `visibleAgents` in sidebar

Suspected Issues:
1. API not returning built-in personas - `/api/persona` may filter out negative IDs
2. AgentsProvider not receiving correct initial data - Server-side props may not include built-in personas
3. Backend query filtering - `persona.py` may have additional filters

**Acceptance Criteria**:

3. [ ] "My Documents" link restored (if feasible)

### Key Findings

#### ROOT CAUSE IDENTIFIED
**The bug is in `AppProvider.tsx:42`:**
```tsx
pinnedAgentIds={user?.preferences.pinned_assistants || []}
```
When `pinned_assistants` is `NULL` (from database for existing users), this expression evaluates to `[]` (empty array), NOT `null`.

In `getPinnedAgents()`:
- If `pinnedAgentIds` is `undefined`/`null` -> Returns default personas
- If `pinnedAgentIds` is `[]` (empty array) -> Returns empty array (truthy!)

The `|| []` fallback converts `null` to `[]`, triggering the "user explicitly has no pins" path instead of "show defaults" path.

#### Relevant Patterns Found
- **Persona filtering** in `persona.py:353-365`:
  - `include_default=True` includes builtin_persona
  - Visibility is controlled by `is_visible` flag
  - Public access requires `is_public=True` AND `is_visible=True`
- **Pinned assistants assignment** only happens on user creation, not login

#### Existing Similar Features
- **Chosen assistants ordering** in `utils.ts:67-117` - similar pattern for ordering by user preference
- **Hidden/visible assistants** - separate fields `hidden_assistants`, `visible_assistants` in User model

#### Important Constraints
- Persona ID 0 is the "unified agent" and is always filtered from sidebar display
- `builtin_persona` flag indicates system personas (cannot be user-edited)
- `is_default_persona` flag determines which personas show when user has no pins

### Recommended Approach

Based on research, here's what I recommend:

1. **Fix AppProvider.tsx (Primary Fix)**:
   Change line 42 from:
   ```tsx
   pinnedAgentIds={user?.preferences.pinned_assistants || []}
   ```
   To something that preserves `null` when `pinned_assistants` is null:
   ```tsx
   pinnedAgentIds={user?.preferences.pinned_assistants ?? undefined}
   ```
   Or pass the raw value and handle in AgentsContext.

2. **Alternative: Backend Migration (One-time fix)**:
   Run SQL to populate `pinned_assistants` for existing users:
   ```sql
   UPDATE "user"
   SET pinned_assistants = (
     SELECT json_agg(id ORDER BY display_priority NULLS LAST, id)
     FROM persona
     WHERE is_default_persona = true AND is_public = true AND is_visible = true AND deleted = false
   )
   WHERE pinned_assistants IS NULL;
   ```

3. **Model Configuration**:
   - Global default: Edit `llm_provider_options.py` - already set to `claude-sonnet-4-5-20250929`
   - Per-persona: Update `llm_model_version_override` on specific persona records
   - Admin UI: Can also configure via Admin Panel > LLM Providers
