# KV-3001: Upgrade LLM Models to Claude 4.5 Family

## Summary

Upgrade the staging Kevin instance to support Claude Haiku 4.5, Sonnet 4.5, and Opus 4.5 on AWS Bedrock. This is a targeted dependency and configuration upgrade — no LLM logic changes.

## Background

The staging box runs older code from the `servicetrade` branch with litellm 1.66.3, which only knows about Claude 3.x models. Users need access to the Claude 4.5 model family for improved quality and capability.

## Target Models

| Model | Bedrock ID (us. cross-region) | Anthropic Direct ID |
|---|---|---|
| Haiku 4.5 | `us.anthropic.claude-haiku-4-5-20251001-v1:0` | `claude-haiku-4-5-20251001` |
| Sonnet 4.5 | `us.anthropic.claude-sonnet-4-5-20250929-v1:0` | `claude-sonnet-4-5-20250929` |
| Opus 4.5 | `us.anthropic.claude-opus-4-5-20251101-v1:0` | `claude-opus-4-5-20251101` |

## Research Findings

Full Claude 4.5 Bedrock support (all three models, bug-free) requires litellm >= 1.80.8. litellm 1.80.5+ requires openai >= 2.8.0 (SDK v2). Research confirmed:

- **openai v2 code impact: ZERO** — the only v2 breaking change (Responses API type) doesn't affect any code path in this codebase. Direct openai usage is limited to 2 production files (embeddings client + auth error), both using unchanged APIs.
- **langchain-openai 0.2.9 blocks openai v2** (`openai<2.0.0`) but is **never imported** anywhere in the codebase. Safe to remove or bump.
- **llama-index 0.12.28 blocks openai v2** via transitive dep `llama-index-llms-openai`. But the codebase only uses `SentenceSplitter` from `llama_index.core`. Safe to replace with `llama-index-core`.

## Acceptance Criteria

- [ ] Users see only Claude Haiku 4.5, Sonnet 4.5, and Opus 4.5 in the chat model dropdown
- [ ] Default model is Haiku 4.5 (cost-efficient default)
- [ ] All three models return responses when chatted with
- [ ] RAG/search works with correct context windows (200K tokens, not 4K fallback)
- [ ] Model names display as friendly names (e.g., "Claude Haiku 4.5") not raw IDs
- [ ] No regressions in existing functionality (connectors, search, chat)
